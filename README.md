# Foogle

The fake/future Google. You use it exactly like Google: type a query, get a results page. The difference is that none of it exists — the search results are invented by an LLM, and when you click one, that webpage gets **vibe-coded on the spot**, streamed into your browser so you watch it build itself. Links inside generated pages route back through Foogle, so the fake internet is browsable forever.

## Setup

Requires Node.js 20.12+.

```sh
cp .env.example .env   # then put your keys in it
npm install
npm start              # http://localhost:3000 (--port N to change)
```

Foogle runs on one stack, the one that won the comparison in [EXPERIMENTS.md](EXPERIMENTS.md):

- **GPT-6 Luna via OpenRouter** writes the search results, the pages and the pictures. Set `OPENROUTER_API_KEY`.
- **Jev** picks each generated site's kind (forum, store, wiki…) and rates how plausible each of 22 design styles is for it — Swiss grid, 1996 homepage, Craigslist-dense, glossy SaaS, scrapbook, terminal, luxury, phpBB board, broadsheet, Win95 and more (`lib/styles.js`) — in one ~0.3s request. The domain then draws one of the plausible styles, so two forums rarely look alike. Set `TYPESAFE_API_KEY`. Without it, or if Jev takes over 1.8s, a site gets one of the styles its kind usually wears, based on the kind of result you clicked.
- **Pictures are SVGs** Luna draws in one of 22 media: photos, phone snapshots, product shots, 3D renders, blueprints, diagrams, charts, screenshots, maps, memes, woodcuts, watercolours, oil paintings, pixel art, posters, collages, stickers and more (`lib/images.js`). Each takes ~3-6s, from whichever of Luna's providers is writing fastest, costs ~$0.0005, and paints itself in as it's drawn. A generated site picks one medium to suit its kind and mood (a store gets product shots, a paper-mood wiki woodcuts or watercolours) and its pictures are drawn in that medium and its palette.

## How it works

- `GET /` — Google-clone homepage, with the day's Foogle Doodle in place of the logo.
- **The Foogle Doodle** (`lib/doodle.js`). Once a day, by UTC date, the model invents an occasion from Foogle's world (an invented inventor's birthday, a holiday of the 2060s, the anniversary of something that never happened) and draws a scene for it in one of the picture media. The scene replaces the logo on the homepage: hovering it shows the occasion, and clicking it searches for it. The model never draws the letters. Code draws "Foogle" over the scene in rounded strokes with an outline, finished to suit the medium (a torn-paper edge, a neon glow, a glossy highlight). The prompt says where each letter will be, so the scene plays with them (characters at both ends, something seen through the o's, a bird on the l) and the word is always legible. The doodle is drawn in the background at startup and just after each UTC midnight, so no visitor waits for it. Until it is ready, or if drawing it fails (it tries again later, three times a day at most), the homepage keeps the plain logo. Each day's doodle is kept in memory and in the image disk cache, so a restart doesn't draw it again. `GET /doodles` lists every day's doodle in the disk cache, and `GET /doodle/<date>.svg` serves one. Set `FOOGLE_DOODLE=0` to turn it off.
- `GET /search?q=…&page=N` — streams a results-page shell instantly, then asks the model (three concurrent shards) to invent ~9 fictional sites for the query, rendered one by one as they stream: site name and favicon, date, a type badge with a rich detail line (rating, price, answers, runtime) and sitelinks. A **Foogle Overview** panel (direct answer, key facts, People also ask) generates alongside and streams into the right-hand column without moving the results; related searches close the page. Pages 2–10 ("Foooooooooogle") dig into more niche sites. "I'm Feeling Lucky" 302s straight to the first one; with an empty box it picks a random query.
- **Search suggestions** as you type, like Google's (`lib/suggest.js`, `public/suggest.js`, `GET /api/suggest?q=…`), under the homepage box, the results page box and the browser's address bar. Your recent searches come first (localStorage `foogle.recent`, newest first, up to 50, each with a Remove link); then up to 8 suggestions a model writes for what you've typed, streamed a line at a time: specific, plausible and sometimes futuristic searches, with a real, well-known site the text starts to name (the model decides: `cn` → cnn.com) at the top with its favicon, going straight to that site. With the box empty you get your recent searches and trending ones. Arrow keys put a suggestion in the box, Esc puts back what you typed, Enter or a click searches, and phones get a fill-in arrow on each row. Short text goes to Llama 3.1 8B on Groq (the first suggestion ~140ms after the request) and text of 12 characters or more to Llama 3.3 70B (better at long queries). Every list goes into an LRU shared by all visitors, and the browser keeps every list it fetched and filters them as you type, so most keystrokes don't wait for the network: in `scripts/suggest-latency.js` (real model, typing at ~75 wpm) suggestions for the text were on screen at 0ms p50 and 100-160ms p90 when the typist paused (the full list by ~235ms p90). The `/api/suggest` JSON (`{"q","suggestions":[{"type":"site","q","domain","title"} | {"type":"search","q"}]}`, or NDJSON with `&stream=1`) is for any other box. Over a limit, or when the model is slow or failing, there is simply no dropdown.
- **Instant answers and "Did you mean"** (`lib/answers.js`, `lib/answer-cards.js`, `public/fw/answers.{js,css}`). On page 1 of the All tab, one Jev request (~0.2–0.3s, sent alongside the result shards, so nothing waits for it) decides whether the query calls for an answer card, whether it gives the card anything to work on, and how likely it is to contain a typo. Cards: weather (now, an hourly chart and 8 days), a calculator, unit and currency converters, sports scores and fixtures, stocks (price, change, a chart for 1D–5Y), dictionary definitions (with pronunciation), time zones and flight status. Code computes whatever it can: arithmetic, conversions, clocks for 90 cities, rates for 35 currencies, and every chart's series. A tool asked for with nothing in it ("calculator", "convert units", "currency converter", "what time is it") opens at Google's defaults with no model call: the calculator at 0, a meter in centimeters, a dollar in euros, and the visitor's own clock, which their browser fills in. The model (Luna) only fills a small typed JSON object for the rest, including invented places, companies and currencies (weather on a Mars colony, a stock that doesn't exist yet). Code then checks it and makes it consistent before drawing it: a score is the sum of its quarters, the chart ends at the price, now lies inside today's high and low. The card's slot is reserved the moment Jev answers, usually a second before the first result, so the results never move when it fills. The calculator's keys, the converters' inputs, the weather's day switcher and °C/°F toggle, chart ranges and hover, and the pronunciation button all work, run by one trusted script shared with the server. For a likely typo, one short Luna call proposes a spelling. The correction is shown only if code agrees it's a small respelling of a word or two, never a rewrite or a renamed invention. Most queries get neither, so they cost only the Jev request.
- `GET /images?q=…` — image search: a justified grid of AI-generated pictures in mixed media and aspect ratios (each result names its style and shape), each clicking through to the (generated) site it "came from".
- `GET /news?q=…&page=N` — Google News-style coverage of the query from invented outlets, with generated thumbnails.
- `GET /maps?q=…` — a local pack of invented places (ratings, hours, addresses) beside a generated map with matching A–F pins.
- `GET /timelines?q=…` — a chronology of the query from its origins into the 2080s; future events are marked with filled dots.
- `GET /img/<description>?s=<style>&a=<shape>` — on-demand SVG picture, used by the Images/News/Maps tabs and by `<img>` tags in generated pages. `s` is a medium from `STYLES` in `lib/images.js`, `a` is `square`, `landscape`, `wide`, `portrait` or `tall`; both are optional, and without `s` the style is inferred from the description ("pixel art of…", "cutaway of…"). Sanitized and served with a locked-down CSP. Cached; falls back to a gradient placeholder on failure. While a picture is being drawn, an `<img>` asking for it (`Sec-Fetch-Dest: image`) gets a `multipart/x-mixed-replace` response, each part replacing the last: a sketch of the picture's colours at once (its light, colour scheme or site palette, out of focus), then a sanitized draft of what the model has written so far, up to four a second, then the picture. So pictures paint themselves in, on results pages and generated sites alike, with no script. Result tiles show the same sketch in CSS the moment their line arrives. A picture someone is waiting for is drawn ahead of one for a prefetched page (24 at once).
- `GET /web/<domain>/<path>` — the fake web. On first visit, Jev picks the kind and style, code renders the styled header at once (the style decides palette, type, density, component skins and the header, hero and section layouts), and four concurrent calls write the page's sections, streamed to your browser as they're written. Generated pages only link to other `/web/…` paths, so every click works. Query strings are part of the page (`/search?q=a` and `?q=b` are different pages), and query forms (search, filters) redirect to the equivalent GET, so search boxes on fake sites work. Invented sites share the page archetypes of the real-site design system (`inventedPageType` in `lib/design.js`), drawn in their own style: a forum's root, or a board its own links lead to, is a feed of threads rather than another thread; a news site's root is a front page; a shop's product URL is a product page with its price, options, add-to-cart and reviews; a wiki's root is its main page (a deep link from a search result stays the page it names). A site keeps the look of its first page, and its pictures are drawn in its medium and palette (`/img/…?s=&a=&bg=&fg=`). The top two search results start generating as soon as they appear, so the likeliest clicks open instantly.
- **Real sites look like themselves, and nothing about them is hardcoded.** There is no list of real sites and no per-site template. The first batch of search results decides whether the query names a real, well-known site (`cnn`, `reddit sourdough`, `letterboxd`): if so, its first line is that site's real page, marked real, with Google-style sitelinks, and it is ranked first, at no extra latency (see `REAL_SITE_RULE` in `lib/prompts.js`). On a direct visit (`cnn.com` typed in the address bar) Jev judges it, in the same request as the layout. A real site's design is then written by the model once (`lib/sitespec.js`): what it is and which structure its pages have (a news portal, a newspaper, a community of threads, an encyclopedia, a marketplace, a video platform, a code host, Q&A, social, streaming, a product maker, classifieds, a landing site), its colours, type and wordmark, its header and rails, its URL scheme, a small SVG icon it draws, and up to 30 scoped CSS rules for the final touches (sanitized: no `url()`, `@import` or fonts, nothing aimed at Foogle's UI, no resizing the page's structure). The spec streams as four concurrent calls, then a fifth for the URL scheme and CSS, written knowing the look so the two agree; about $0.0005 a site, once. One generic renderer, `lib/design.js`, draws any spec from primitives named for what they are (header rows, a masthead, rails, a buy box, a player, an infobox, tabs, a contents box…), and the section writers are told which site they imitate, its voice and its URL scheme, so links lead to more pages of the same site in the right layout. Specs are cached in memory and on disk (`.foogle-cache/sites/`), so every page of a site shares one look. A search result marked real starts its spec (and page) at once, so a click after a moment's reading opens instantly; a cold direct visit shows a neutral header at once, starts the writers on the spec's first line and swaps in the styled header when the look arrives, about 2.5s in.
- **Fake sites are interactive.** Section writers use plain HTML with `data-*` attributes (add to cart, filterable grids, tabs, quizzes, calculators with live formulas, polls, pick-one chips, toggles, modals, countdowns, comment boxes) and one trusted runtime, `public/fw/widgets.js` + `widgets.css`, makes them work in each site's palette. Posts get working votes and replies, headers get working log-in/sign-up and cart drawers, and tables sort (and scroll sideways rather than widen a phone's page). Server-side state (`lib/interact.js`, in memory, keyed by an `fv` visitor cookie) keeps a cart per site, the visitor's login, and comments per page; someone on the site answers a posted comment a few seconds later. A form that does something (checkout, sign up, booking, contact) is answered by a confirmation page at its own URL (`?order=4821`, `?ref=K7Q2`) that opens with an exact, code-built receipt. Model-written JavaScript never runs: sections are sanitized as they stream (`lib/widgets.js`) and `/web/` pages are served with a Content-Security-Policy that only allows Foogle's own scripts.
- **Foogle opens in a browser of its own** (`lib/browserbar.js`, `public/fw/browserbar.{js,css}`, `public/fw/browsing.js`). Every top-level visit gets a small shell page with tabs, back / forward / reload and an address bar showing the URL a real browser would: `https://crumbforum.net/threads/starter-smells` for `/web/crumbforum.net/threads/starter-smells`, `https://www.foogle.com/search?q=…` for Foogle's own pages, and nothing (just a placeholder) on the homepage, which doubles as the new-tab page. Each tab is an iframe showing the page itself, served exactly as without the browser (the same URL answers both; the shell only for `Sec-Fetch-Dest: document`), so a background tab keeps what it loaded, pages can't cover the bar, and each tab has its own history, which the real back button and a phone's back gesture follow. Middle-click and ⌘/Ctrl-click open links in new tabs; tabs outlive reloads (sessionStorage); phones get one row and a tab switcher. The address bar works like Chrome with Google: a URL or domain (`cnn.com`, `en.wikipedia.org/wiki/Foo`) goes to that fake site, anything else is a Foogle search, and suggestions appear as you type: the search, recent searches (localStorage `foogle.recent`, which omnibox searches join) and the model's suggestions from `/api/suggest`, including the real site the text heads for (`cnn` → cnn.com). Without the script the address bar is a GET form to `/go`. Set `FOOGLE_BROWSER_BAR=0` to turn it all off.
- Pages and result pages are cached in memory (capped, FIFO), so the back button is instant and a fake site stays consistent within a session. Restarting the server wipes the fake internet — except images, doodles and real sites' design specs, which also persist to a disk cache (`.foogle-cache/`) since they're the most expensive assets (fake and replay modes keep specs in memory, so they follow the fixtures). Delete that directory to regenerate them.
## Cost

Measured on 2026-09-23 with OpenRouter's reported usage (`usage: {include: true}`), GPT-6 Luna at $0.10/$0.50 per million tokens in/out, over a few real runs of each action. "Calls" are Luna calls; Jev calls are listed separately (TypeSafe reports tokens, ~330 in / 32 out per call, but no price, so they're not in the dollars). Anything already cached (a result page, a site page, a picture, or a page still being generated) costs nothing.

| Action | Cost | Calls | What's in it |
|---|---:|---:|---|
| Search, page 1 | $0.0060–0.0068 | 18–20 + 3 Jev | 3 result shards + Overview ≈ $0.0007; prefetching the top 2 results' pages is the rest. One of the Jev calls classifies the query for instant answers |
| + an instant answer the model fills | $0.00003–0.00021 | 1 | sports ~$0.0002, weather ~$0.00016, dictionary ~$0.00012, flights and stocks ~$0.00009, invented currencies, clocks and worded sums ~$0.00003–0.00005. Calculator, unit and known-currency cards, clocks for known cities and tools asked for with nothing in them are free |
| + "Did you mean" | ~$0.00002 | 1 | only when Jev thinks the query has a typo |
| Search, pages 2–10 | ~$0.006 | ~19 + 2 Jev | the same without the Overview |
| Page (`/web/…`) | $0.0030–0.0033 | 7–8 (+1 Jev on a site's first page) | fact sheet, 4 sections, 2–3 pictures |
| Form confirmation page | ~$0.0012 | 4 | fact sheet, 2 sections, 1 picture |
| Comment reply | ~$0.00003 | 1 | one short reply |
| Search suggestions for a typed query | ~$0.0009–0.0014 ($0.0002 when others typed it before) | ~9–10 small calls | one call per prefix the browser's lists can't fill; lists already cached (by anyone) are free. See EXPERIMENTS.md |

## Limits

Once Foogle is public, every visitor is spending your OpenRouter credit, so `lib/limits.js` puts two limits on it. Both apply only to fresh generations: cached responses are free and don't count.

- **Per visitor** (by IP; an IPv6 /64 counts as one visitor), a budget in dollars that refills over time. Each action is charged its measured cost from the table above, so a search costs about two pages and a picture a sixth of one. An instant answer or a "Did you mean" that needs the model is charged on top (`answer`, `spell`). A visitor out of budget still gets the results, just without them. Over the limit, the visitor gets a Foogle-styled "slow down" page (429 with `Retry-After`; pictures get a blank placeholder instead). A comment still posts, it just gets no reply.
- **Per day, for the whole site**, a spend circuit breaker tracked from the cost OpenRouter reports for every call. Once it's reached, new generations stop and visitors get "Foogle is out of juice for today" (503) until midnight UTC. Calls already in flight finish, so the day can overshoot by a few cents. The daily doodle counts toward it like everything else. No visitor is charged for the doodle, and it isn't drawn once the day's budget is spent.

| Variable | Default | Meaning |
|---|---|---|
| `RATE_LIMIT_BURST_USD` | `0.10` | How much a visitor can spend at once (~14 searches or 30 pages) |
| `RATE_LIMIT_USD_PER_HOUR` | `0.40` | How fast their budget refills (a new page every ~30s) |
| `DAILY_BUDGET_USD` | `5` | Site-wide spend per UTC day (~250 typical sessions); `0` stops all generation |
| `TRUST_PROXY` | unset | Unset: use the connection's address and ignore forwarded headers. `1` (or `N`): the last (Nth-from-last) `X-Forwarded-For` entry, for N proxies you run. `true`: the first entry. A header name (`fly-client-ip`, `cf-connecting-ip`): that header |
| `SUGGEST_MODEL`, `SUGGEST_MODEL_LONG`, `SUGGEST_LONG_AT` | Llama 3.1 8B, Llama 3.3 70B, `12` | Search suggestion models: the fast one for short text, the other from `SUGGEST_LONG_AT` characters (`SUGGEST_PROVIDER`, default `groq`, is the OpenRouter provider order). `SUGGEST_WARM=0` stops the first visitor's typing from pre-writing the empty box and the 26 first letters (~$0.0007) |

Set any of the first three to `off` to disable it. Behind a proxy you must set `TRUST_PROXY`, or every visitor shares the proxy's address and one budget. Only set it behind a proxy, though, since anyone can send a forwarded header. `GET /api/whoami` shows how the limiter sees your request: the address and bucket it charges, the forwarded headers it had (names, plus the values of `X-Forwarded-For`, `True-Client-IP` and `CF-Connecting-IP`), and what each other `TRUST_PROXY` setting would pick. It is free and only ever describes the request itself. The state is in memory, which is right for one instance; it resets on restart.

## Deploy

Foogle deploys to Render's free web service tier from [`render.yaml`](render.yaml), a Render Blueprint. It builds with `npm ci`, starts with `npm start` on Node 22 and health-checks `/`.

CI deploys each push to `main` to Render once the tests pass, then waits for that commit to go live and checks the site answers 200.

1. Create a dedicated OpenRouter key for the deployment at [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys). Give it a **credit limit** (a few dollars), so a runaway bill is impossible, and **no expiration date or a distant one**, so the site doesn't stop working without warning.
2. In the [Render dashboard](https://dashboard.render.com), click **New > Blueprint** and pick this repo (connect GitHub first if asked).
3. When prompted, paste `OPENROUTER_API_KEY` (the new key) and `TYPESAFE_API_KEY`, then click **Deploy Blueprint**.

The Blueprint also sets `TRUST_PROXY=cf-connecting-ip` and `DAILY_BUDGET_USD=1`. Render sits behind Cloudflare and a proxy of its own: the rightmost `X-Forwarded-For` entry is Render's proxy, which every visitor shares, and the leftmost is whatever the visitor sent, so visitors are rate-limited by Cloudflare's `CF-Connecting-IP` instead. Visit `/api/whoami` on the deployed site to check it. Change these under the service's **Environment** tab. Render asks for secrets only when the Blueprint is first created, so add any new ones there too.

On the free tier the service sleeps after 15 minutes without traffic, and the next visit takes up to about a minute to wake it. Its filesystem is ephemeral, so the image disk cache (`.foogle-cache/`) starts empty after each deploy or restart and only saves repeat work while the instance is up.

## Developing

Most changes are to layout, UI or interactivity, and none of those need the real model:

```sh
FOOGLE_FAKE_LLM=1 npm start   # the whole site with canned model output: no keys, no network, no cost
npm run shots                 # screenshots of 37 representative pages at two widths, plus a contact sheet
```

- **Fake model.** With `FOOGLE_FAKE_LLM=1`, every model call and every Jev call gets instant, canned output (`lib/fake-llm.js`, fixtures in `lib/fake-fixtures.js`). That covers search shards, the Overview, fact sheets, page sections, pictures, News/Maps/Timelines, comment replies, confirmation pages and the daily doodle. The output is built from the prompt in the real formats: result lines, sections made of the real components and interactive widgets, SVGs in every medium, and sites of every kind in varied styles. So the real parsing, streaming, sanitizing and rendering code all runs. The same query or URL always gives the same page, and different ones differ. Output streams in 32-character chunks, `FOOGLE_FAKE_LLM_DELAY_MS` apart (default 3; 0 for none). A site gets any design style its URL names, as in `/web/zine.example/web1996/issue-1`. Fake pictures are cached under their own model name, so they never mix with real ones.
- **Record and replay.** `FOOGLE_LLM_CACHE=record` saves every real model and Jev response, keyed by a hash of its prompt, to `FOOGLE_LLM_CACHE_DIR` (default `.foogle-cache/llm`). `FOOGLE_LLM_CACHE=replay` answers from those files without touching the network. Capture one real run, then iterate against it for free. A prompt that wasn't recorded gets canned output, with a warning in the log. Like fake mode, replay caches pictures under its own model name.
- **Screenshots.** `npm run shots` (`scripts/shots.js`) starts Foogle in fake mode on a free port and stops it afterwards. It visits the home page (with the day's doodle), the doodle archive, the All, Images, News, Maps and Timelines results, a store, a forum, a news site, a wiki, a 1996-style zine, a calculator and a quiz. It also shoots an open cart and a checkout confirmation. And it shoots every instant-answer card, each put through its interaction (keypad presses, a day switch, a converter edit, a chart range), the calculator, converters and clock asked for with nothing in them, and a "Did you mean". Each page is taken at 1280 and 390 px wide, and the PNGs plus `contact.png` go to `.shots/`. A full run takes about 15 seconds. Pages can run scripted steps first (`click`, `fill`, `select`, `check`, `press`, `wait`, `url`), which is how the cart and checkout are captured. The run reports page errors, console errors, horizontal overflow and clicks that something else intercepted. Flags: `--only <regex>` picks pages by name, `--url <base>` uses a Foogle that's already running, `--live` uses the real model (this costs money) and `--out <dir>` sets the output directory. If Playwright's Chromium is missing, the first run installs it.

## Tests

```sh
npm test
```

The tests stub the network and need no keys. They ignore `FOOGLE_FAKE_LLM` and `FOOGLE_LLM_CACHE` if you've exported them, and they don't need Playwright's browsers.
